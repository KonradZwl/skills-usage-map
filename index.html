From idea to merge: which skill, when

A visual guide to building features with agent skills in GitHub Copilot (CLI and VS Code chat). Answer three questions to pick a lane, then follow it. You lead at both ends; the agent runs the middle.

Why one chat matters: models do their best work in the "smart zone": about 150k tokens for the whole chat (every message, file read and test run). Check it with /context in Copilot CLI or the context indicator in VS Code chat. If you can't tell, take the longer route: it costs some ceremony, but every ticket starts in a fresh chat. These numbers are rules of thumb, not hard limits.

Before the first task: set up once

Step 1

Install the skills

Copilot CLI: add the skills marketplace, then install the plugin.

copilot plugin marketplace add mattpocock/skills
copilot plugin install mattpocock-skills@mattpocock

VS Code: run Chat: Install Plugin From Source and enter the repo URL.

Company tip: these are third-party instructions that run with your permissions. Don't auto-update from the public repo: fork it into an internal repo (or pin a version), review changes before the team gets them, and point the commands above at your fork.

Step 2

Check they loaded

In VS Code chat, type /skills to open the skills list. In Copilot CLI, run /skills list. You should see grill-with-docs, to-spec, implement-spec and retro. If the install is blocked, check your organisation's Copilot policies with your admin.

Keep approvals on. Don't use /allow-all or /yolo, and don't run agents in a folder with production credentials or secrets.

Step 3

Run setup once per repo

Not optional. /to-spec, /to-tickets, /wayfinder, /implement-spec and /code-review (which /implement also runs) all stop and ask for it. Only grilling works without it.

It asks where issues live, which triage labels to use, and where GLOSSARY.md and docs/adr/ go. If it asks which instructions file to create, pick AGENTS.md: Copilot reads it.

No GitHub Issues needed: pick local markdown and specs and tickets become plain files in a .scratch/ folder in the repo. Nothing is created in GitHub or Azure DevOps, and the whole workflow still works.

Commit the files it writes (docs/agents/ and the AGENTS.md block): then teammates don't run it again. Only if you pick GitHub Issues do you need the GitHub CLI (gh) installed and signed in.

Step 4

Make the repo agent-ready

Build, test and lint must each run with one command and pass on main. /tdd and /implement need to run your tests, and CI is the check the agent can't talk its way past.

Add a CODING_STANDARDS.md (or CONTRIBUTING.md). /code-review checks every diff against it, and /retro proposes additions. GLOSSARY.md and ADRs are created as you grill, so you don't need them up front.

Commands at a glance

Where your time goes

The zones on the map: you spend your attention at the edges, not in the middle.

You lead: alignment

Grilling, naming, ADRs, prototype choices. Every decision you make here is one the agent can't get wrong later.

Agent runs mostly unattended

A spec plus tickets, or a clear grilling chat, leaves almost no decisions. Start it and step away.

You lead: review + retro

QA, taste, coding standards. Turn every review comment into a rule, so the next run is better.
